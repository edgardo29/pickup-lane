## Important interpretation rules

1. The current working tree remains the only repository source of truth. Prior inventory evidence may be stale if files changed after inspection.
2. A matching route, model, service, test, or configuration file is not enough for `PASS`; every clause of the control needs evidence.
3. `backend/tests/legacy/` is historical scenario material only and must not count as current coverage.
4. Testing guidance documents describe process expectations but do not prove current test coverage.
5. Runtime, provider-dashboard, deployment, backup/restore, access-review, and operational-process claims cannot be proven through static repository inspection alone.
6. Numeric limits, retention periods, retry counts, pool sizes, alert thresholds, RPOs, and RTOs require documented owner decisions rather than invented values.
