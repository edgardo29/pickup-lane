## Trust Boundaries

Browser users interact with the React/Vite frontend and Firebase client authentication. The browser must not hold backend secrets and must treat API and provider client keys according to the selected frontend security policy.

The FastAPI API is the server-side trust boundary for authorization, database writes, Stripe secret-key operations, Firebase Admin calls, and R2 signed URL creation. CORS and security headers need explicit app/edge ownership and runtime verification.

PostgreSQL is the durable application data boundary. PostgreSQL as the technology is fixed, while its final production hosting provider remains late-bound. Provider roles, grants, connection budgets, backup settings, restore behavior, and human access are external evidence until verified against the selected final topology.

Firebase, Stripe, and Cloudflare R2 are provider trust boundaries. Repository SDK calls show integration points only; provider configuration and operational behavior remain external or runtime evidence. Current Vercel, Render, and Neon deployments are prototype/demo hosting boundaries only and do not define the final production hosting architecture.

GitHub Actions is a CI configuration boundary. Workflow YAML does not prove branch protection, secret policy, actual run success, artifact identity, or release approval.
