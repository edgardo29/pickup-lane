# Secret Lifecycle Register

Pass: EN-03.

Primary controls: OPS-006, OPS-007.

Owner role: Secrets and provider access owner, held by Project owner (interim) until reassigned under the approved ownership model.

Evidence basis: repository source, environment examples, README deployment notes, GitHub Actions workflow configuration, GOV-01 governance records, EN-01 and EN-02 planning records, and finalized audit/remediation records. Ignored local `.env` files, provider dashboards, provider APIs, secret stores, and deployed environments were not inspected.

This register records secret and configuration names only. It must never contain secret values, tokens, keys, passwords, signed URLs, cookies, recovery codes, private keys, full connection strings, or raw provider payloads.

## Classification Rules

- `PRIVATE CREDENTIAL`: must be server-side or provider-side only. It must not be committed, logged, copied into frontend bundles, stored in tickets, or shown in screenshots.
- `PUBLIC CONFIGURATION`: can be exposed to the browser, but still requires environment binding, provider-domain restrictions where available, and review before publication.
- `SENSITIVE CONFIGURATION`: is not necessarily a credential, but can expose topology, access surfaces, routing, or provider details. It requires least disclosure and environment-specific review.
- `LOCAL OR TEST CONFIGURATION`: may use synthetic values for development or test only and must not be reused for production.

## Public And Private Boundaries

Browser-public Firebase configuration is separate from Firebase Admin credentials. Stripe publishable keys are separate from Stripe secret keys and webhook secrets. Public URLs are separate from signed/private URLs. Configuration values are separate from credentials. This register records names and lifecycle expectations only; it does not record current values.

## Non-Closure Statement

This register improves OPS-007 evidence by naming secret categories, lifecycle expectations, and current gaps. It does not prove managed secret storage, provider-side injection, production environment separation, current secret values, successful rotation, revocation, emergency response, offboarding, or short-lived workload identity.
